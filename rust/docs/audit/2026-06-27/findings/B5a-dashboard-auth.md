# B5a Dashboard-Auth/Admin/Billing/Partner HTTP-Paritaet

## Scope

- Auftrag: Read-only Paritaetspruefung der Python-Dashboard-HTTP-Flaeche gegen Rust `tb-dashboard-api`/`tb-dashboard`.
- Quellen: `bot/dashboard/*`, `bot/admin_dashboard/*`, `bot/dashboard_service/*`, `bot/entitlements/resolver.py`, `bot/analytics/*`, `rust/crates/tb-dashboard-api/src/*`, `rust/bin/tb-dashboard/src/main.rs`.
- Baseline gelesen: `rust/docs/audit/2026-06-27/00-baseline.md` Abschnitt 2. Bewusste Abweichungen aus dem Intent-Ledger werden nicht als Regression gewertet: haertere Dashboard-Auth, keine Go-Live-Builder/PDF/Discord-DM-Eigenlogik, Stripe-hosted Billing.
- Betriebsannahme: Rust-Ziel ist der native Router aus `rust/crates/tb-dashboard-api/src/lib.rs`. Der optionale Legacy-Fallback in `rust/bin/tb-dashboard/src/main.rs:47-64` zaehlt nicht als native Paritaet, weil er nur bei `TB_DASHBOARD_LEGACY_FALLBACK_URL` aktiv ist.
- Methode: harte `rg`/`nl`/`sed`-Inventur, keine Secrets, kein `git`, keine Codeausfuehrung gegen Produktivdienste.
