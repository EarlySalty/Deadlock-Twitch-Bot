# Streamer AI policy

`public.twitch_streamer_ai_policy` bridges the per-server switch without depending on the parallel guild-onboarding schema. Its primary key is the canonical Twitch user ID; `guild_id` records the owning Discord guild, and `ai_features` defaults to false. The migration assigns existing canonical identities to home guild `1289721245281292288` with AI enabled. Subsequent registrations through the existing home-scoped OAuth promotion, admin promotion and manual registration paths insert an enabled home policy in the same transaction as the canonical identity. Existing policies are never overwritten, so foreign assignments and explicitly disabled home policies remain authoritative. Monitoring-only identity creation does not grant AI access.

Guild onboarding and membership changes must write this mapping atomically with their own authoritative membership. New foreign-server members remain disabled by default. New home-server registrations are initialized by the existing home registration paths without G. Moving a streamer to a foreign guild must update the guild and disable AI in the same transaction. A guild-wide switch must update its mapped streamers transactionally. Foreign onboarding must assign its disabled policy before invoking any legacy home registration helper in the same transaction. Missing policies outside the home registration paths fail closed. No `discord_guilds` or membership table is required by K1.

The central LLM dispatcher resolves the canonical identity and rejects unknown, missing, conflicting or disabled scopes before provider dispatch and each retry. Brain and social-editor routes use the same policy. Batch requests authorize every source channel; mixed enabled/disabled sources cannot be uploaded. Background learning paths exclude disabled source rows before creating prompts.

The authenticated `/twitch/api/v2/ai/capabilities` endpoint exposes only `aiFeatures`. Dashboard components remain unmounted until authorization is explicitly true. Backend endpoint checks and the central provider guard remain authoritative regardless of browser state. Policy lookup failures return unavailable, not permission. A rejected AI chat turn is a known rejection and does not consume a follow-up allowance.

The migration and runtime-role wrapper grant the existing application roles read access to the identity and policy tables. Only existing trusted database writers manage the mapping. Infrastructure credentials remain in the existing secret manager.
